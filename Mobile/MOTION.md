## На что опираемся

1. **Material Motion, Shared Axis:** связанное движение по оси помогает показать пространственную или навигационную связь. Используем идею для последовательных шагов авторизации. Это адаптация классического паттерна Material, а не утверждение о единственном текущем стандарте Material3. [Официальный Android codelab](https://developer.android.com/codelabs/material-motion-android).
2. **Carbon:** сдержанный productive motion для задач, согласованная семантика движения и непрерывность общих элементов. Продолжаем направление, уже использованное в desktop Prana. [Overview, версия v10](https://v10.carbondesignsystem.com/guidelines/motion/overview/) · [Choreography](https://v10.carbondesignsystem.com/guidelines/motion/choreography/).
3. **Apple HIG:** движение должно поддерживать действие, оставаться кратким, соответствовать обратному жесту и допускать отмену; важные состояния доступны и без движения. [Motion](https://developer.apple.com/design/human-interface-guidelines/motion).
4. **Клавиатура на нативном iOS:** геометрия интерфейса должна учитывать фактическую клавиатуру; UIKeyboardLayoutGuide отслеживает занятую ею область. Числа браузерного макета не являются предписанием для системной клавиатуры. [Документация Apple](https://developer.apple.com/documentation/uikit/uiview/keyboardlayoutguide).

## Реализованная хореография Sign in → Phone

Общее ощущение: последовательное переключение задачи на устойчивой тёмной поверхности. Рамка, status bar, Home Indicator и верхнее скругление панели не перемещаются. Геометрия каждого экрана вычислена заранее; появление Back не меняет координаты уходящего экрана.

Все времена ниже отсчитываются от принятого нажатия. Это **стартовые параметры для визуальной настройки**, а не норматив Apple/Google/IBM.

| Время | Что происходит | Начальные параметры |
| --- | --- | --- |
| 0–70ms | Немедленный отклик нажатой кнопки | Короткое изменение заливки/opacity, без уменьшения всего экрана |
| 0–140ms | Содержимое Sign in, включая фото, гаснет и слегка уходит влево | x0→−24px, opacity1→0, scale1 |
| 80–320ms | Заголовок Phone, описание, поле, Back и CTA появляются связанной группой | x+24→0px, opacity0→1, scale1 |
| 180–440ms | Клавиатура входит снизу, фокус передаётся полю | Смещение301→0px, длительность260ms для статичной клавиатуры прототипа |
| С320ms | Основное содержимое уже на месте и доступно | Клавиатура завершает движение; отдельного ожидания для пользователя нет |

Для появления движущейся группы — начальная кривая Carbon entrance `cubic-bezier(0,0,0.38,0.9)`, для ухода — exit `cubic-bezier(0.2,0,1,0.9)`. Прозрачность можно менять линейно. Для демонстрационной клавиатуры можно сохранить текущую `cubic-bezier(0.2,0.8,0.2,1)` как отдельный параметр. Главный критерий — мягкое завершение без отскока; значения уточняются по просмотру, а не подгоняются только под формулу.

CTA Phone с первого видимого кадра находится в целевой области над клавиатурой (y552 для текущего макета). Во время входа Phone место под ожидаемую клавиатуру уже зарезервировано. Кнопка не появляется сначала внизу, чтобы затем пересечь ещё267px. Это правило первого появления экрана с автофокусом; последующее ручное закрытие/открытие клавиатуры по-прежнему двигает закреплённую кнопку согласованно с клавиатурой.

Заголовок, описание и поле не вылетают по очереди отдельными каскадами. Фото не увеличивается, текст не масштабируется и не размывается. Кнопку выбора способа входа не превращаем морфингом в кнопку отправки SMS: это разные действия.

## Переиспользуемые правила

| Тип изменения | Семантика первой реализации |
| --- | --- |
| Следующий шаг одной задачи | Короткий сдвиг содержимого влево + затухание; новое приходит справа |
| Предыдущий шаг | Та же ось с обратным направлением; состояние предыдущего шага сохранено |
| Phone → Code | Общий фон, положение CTA и клавиатура сохраняются; меняются тексты и поля. В браузерном прототипе один и тот же PNG не должен закрываться и открываться заново |
| Открытие модальной панели | Отдельная вертикальная механика и работа с нижележащим экраном; не смешивать со сменой шага |
| Ошибка в поле | Локальное изменение поля/сообщения, без перезапуска анимации всей страницы |

Дополнительные правила для реализации:

- Один управляющий процесс задаёт направление, текущий прогресс и политику клавиатуры для перехода. Отдельный свободно живущий таймер фокуса320ms убрать; фокус привязать к фазе перехода с отменой устаревшего действия.
- Back или новая команда отменяет прежнюю последовательность и продолжает из текущего видимого состояния. Повторный тап той же команды не создаёт второй экземпляр маршрута. Старый callback не должен фокусировать уже закрытое поле.
- Уходящий контент становится inert/aria-hidden и перестаёт перехватывать касания; экран не блокируется целиком до окончания анимации.
- Reduced motion: без пространственных сдвигов/scale; короткий fade до100ms либо мгновенная смена. Та же конечная геометрия, фокус и доступность действий. Движение декоративной клавиатуры также отключается.
- Для authStep правило шаблона о `keyboard.hide()` на каждой навигации заменено в D-42 передачей фокуса между полями. Это изменение запрошенного runtime-перехода; остальные ветки и панели сохраняют прежнюю политику.

## Дальнейшая оценка

Передавать именованный preset `authStep`, направление, длительности, расстояние24px, easing и политику фокуса/клавиатуры вместе с отдельными конечными layouts. Состояния `idle`/`transitioning`, направление и отмена реализованы; текущий этап также доступен как `data-current-step` для QA.

Оставшиеся проверки: системный reduced motion, физический touch/edge-swipe и нативная клавиатура, воспроизведение с записью на целевой платформе. В следующей настройке менять ритм по визуальному просмотру, сохраняя геометрию, отмену и передачу фокуса.
