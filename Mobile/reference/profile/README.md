## Принятые адаптации

- В соответствии с прямым указанием пользователя существующий прототип имеет приоритет: фон#121212, CTA#EA5C00, кнопки600, поля#313030 → #3B3A3A при фокусе. SF Pro подключён через `local()`, без копирования шрифта; fallback — существующий Prana Display.
- Суммы и количество берутся из каталога: пример истории Acai+Buddha —2 позиции/$34.90. Несогласованные цифры Figma исправлены; неверные заголовки пустой/ошибочной истории заменены на My orders, ошибки выхода — на Profile, отменённый заказ согласован как#137.
- Нет отдельного нового tracking: используется действующий экран с двумя положениями D-60. Нет нового адресного движка: используется существующая демонстрационная карта Brickell, а не реальный геокодер Бали.
- Бизнес-правила бонусов, скидок, возвратов и сроков не придуманы. Credits трактуется как сведения о приложении и лицензиях — требуется подтверждение бизнеса.
- Добавлен рабочий путь сохранения карты и выбора default; checkout использует общие карты. Если их нет, оформление блокируется с пояснением добавить карту в профиле. Inline-добавление карты из checkout остаётся отдельным развитием.
- Контакт поддержки не предоставлен: Contact support остаётся недоступным, как в прежнем checkout/tracking. Сообщения никому не отправляются.

## Motion и сохранение контекста

Профиль открывается существующим BottomSheet. Внутри — FlowStack/authStep: неподвижная поверхность,24px, выход140ms, вход240ms с80ms задержкой. Геометрия адресов/SMS меняется320ms. Footer с BottomFade4/12/34 вынесен из opacity-анимации сцен; учитывает клавиатуру и safe area. Hover отсутствует, pressed70/150ms, доступность/цвета180ms. Для reduced motion убрано перемещение внутренних сцен и изменения геометрии; открытие внешнего BottomSheet наследует защищённый runtime и отдельно на системном Reduce Motion не проверялось.

Escape закрывает список стран, затем клавиатуру, затем возвращает по стеку; корневой Escape закрывает профиль. Несохранённые формы и адресные черновики защищены подтверждением. Отмена адреса возвращает в список, не проскакивая на главную. Исходные подписи удалённой карты/адреса остаются до конца исходящего перехода. Успех или уход со страницы отменяет отложенную локальную операцию. App-owned contexts сохраняют идентичность при HMR, поскольку FlowStack удерживает функции уже открытых экранов. При изменении набора hooks во время разработки требуется перезагрузка превью.

## Данные и границы прототипа

Все операции выполняются в памяти текущей вкладки; reload возвращает fixtures. Нет серверной авторизации, SMS, оплаты, банковского SDK, системных push-разрешений, API заказов или постоянного кеша. Имитация банка не передаёт данные наружу. Для QA использована только синтетическая карта4242…4242; в saved-модели остаютсяid/brand/last4/expiry/name, без полного номера и CVC. Это не сертифицированная платёжная интеграция.

Выход закрывает доступ к разделу аккаунта и очищает подтверждённый checkout-телефон; демонстрационные данные приложения остаются в памяти до reload. Полный production logout, отзыв серверной сессии и очистка локального хранилища требуют отдельного контракта с разработкой. Адреса Бали, история,476 баллов, pending+200, промокоды и задержки — fixtures, не обещания бизнеса. Политики/условия временные. Лицензии зависимостей сверены с установленными package.json (MIT, TypeScriptApache-2.0, RobotoOFL-1.1); страница содержит краткие сведения, не заменяет полный release inventory и notices.

## Выжимка для лида и разработки

Проработал полный раздел профиля и настроек: личные данные и телефон, история и повтор заказов, адреса, способы оплаты, баллы, уведомления и информационные страницы. Сразу предусмотрел не только основной путь, но и загрузку, пустые состояния, отсутствие сети, ошибки ввода и сохранения, повторные попытки, недоступные позиции и подтверждение важных действий. Это позволяет заранее согласовать поведение в проблемных ситуациях, сохранить введённые данные при ошибках и дать пользователю понятный путь продолжения. Раздел собран в интерактивном прототипе и связан с существующими входом, корзиной, checkout и отслеживанием; визуал и motion едины с остальным приложением. Для разработки есть карта состояний, проверки и явно отмеченные места будущих интеграций.
