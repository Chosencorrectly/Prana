# Prana — основы анимации

Основа — сдержанное направление **productive motion** из [IBM Carbon](https://v10.carbondesignsystem.com/guidelines/motion/overview/). Для управляемого движения используется [Motion](https://motion.dev/docs/animate), версия 14.0.0. Конкретные назначения ниже адаптированы для Prana; это не перенос всех анимаций Carbon.

## Общие параметры

Единый источник — [src/motion/tokens.js](src/motion/tokens.js). Длительности и кривые экспортируются для Motion; CSS-переменные выводятся из тех же значений и устанавливаются в `main.jsx`.

Шкала длительностей: **70 / 110 / 150 / 240 / 400 / 700ms**. Текущие микровзаимодействия занимают 110–400ms; вертикальный скролл — 400–700ms в зависимости от расстояния.

| Кривая | Значение cubic-bezier | Назначение |
| --- | --- | --- |
| standard | `0.2, 0, 0.38, 0.9` | Перемещение и смена состояния существующего элемента |
| entrance | `0, 0, 0.38, 0.9` | Быстрый отклик на действие с мягким замедлением |
| exit | `0.2, 0, 1, 0.9` | Исчезновение состояния покупки |
| gentleInOut | `0.3, 0, 0.7, 1` | Собственная адаптация Prana для мягкого разгона и остановки вертикального скролла |

## Текущие взаимодействия

Профиль (06.10.2026): поля, кнопки, ссылки и аватар используют controlHover 150ms; заказ — cardEnter/cardLeave 150/240ms только фона. Save changes ↔ Saved переиспользует AnimatedValue 150ms/4px без изменения размеров, неактивность задаётся guarded aria-disabled с сохранением фокуса. Общий SwitchThumb имеет 49×28px, белый thumb 30×24px и travel 15px по toggleState 240ms standard; фон — 150ms. Checkout сохраняет прежний включённый вид и демонстрационное поведение. Popover даты появляется/исчезает по dialogEnter/dialogExit 240/110ms с 4px; месяцы DayPicker используют calendarMonth 240ms standard. Reduced motion отключает CSS transitions/animations и DayPicker animate, Saved использует существующий React-hook. Нет нового page entrance. [Проверка профиля](reference/profile-browser-audit.json).

Фон карточки при hover — **#181818**: `cardHoverBrightness = 1.5` применяется через relative RGB к #101010. По обратной связи пользователя эффект смягчён относительно прежнего #1C1C1C (×1.75). Фото и текст не фильтруются; кнопки получают собственный hover, теги сохраняют заливку. Базовая палитра и размеры карточек прежние. Видимый клавиатурный фокус даёт такой же отклик. У неактивной категории hover — Gray 100 с основным текстом; активная при hover становится чисто белой. Ширины, паддинги и веса текста пунктов не меняются.

CSS отвечает за цвета и затухание окружения поиска; Motion — за прокрутку, смену содержимого покупки и появление/перестройку результатов. В библиотеке не дублируются CSS-переходы.

## Вертикальная навигация

`page-scroll.js` использует тот же движок Motion и CSS scroll-margin-top. Отдельная симметричная кривая `gentleInOut [0.3, 0, 0.7, 1]` даёт нулевую скорость на старте и в конце, с умеренным разгоном между ними; остальные кривые не изменены. Время в секундах: min(0.7, max(0.4, 0. 24 + sqrt(расстояние) × 0.004)). Новая категория заменяет текущую цель из видимой позиции; старое завершение защищено номером запроса и не может завершить новый маршрут.

Выбранная категория выделяется сразу и удерживается до завершения скролла. Промежуточные секции не перехватывают выделение. Колесо, touch, клавиши прокрутки/Tab, обычный pointerdown и изменение размера окна прерывают движение и возвращают управление определению активной секции. Клик на другую категорию или логотип меняет цель напрямую. Поиск тоже отменяет текущий маршрут. Конечная позиция ограничена реальной длиной страницы.

## Покупка и количество

Пользователь 05.10.2026 явно положительно оценил анимации добавления и изменения количества. При настройке hover и вертикального скролла эти переходы сохранены.

Переходы построены на [AnimatePresence](https://motion.dev/docs/react-animate-presence) и Motion React из уже установленной библиотеки. Строка покупки остаётся высотой 40px. Исходящее состояние сразу получает inert и aria-hidden, поэтому не перекрывает новые действия и не остаётся в порядке Tab. Кнопки работают во время анимации, быстрые нажатия не ждут окончания перехода. Число и сумма обновляются вместе, с табличными цифрами и отдельным актуальным сообщением для assistive technology. Визуальные уходящие копии скрыты от неё.

При клавиатурном добавлении фокус переходит на плюс; при удалении последней единицы — на Add. Иконки появляются внутри прежних слотов. Сильного масштаба, bounce и изменения геометрии карточки нет.

PDP от 05.10.2026 переиспользует тот же QuantityControl через variant="detail": исходная кнопка 44px с Add to cart, счётчик — прежний компактный. Длительности, кривые, inert, reduced motion и обработка кликов общие с каталогом. Переходы между страницами мгновенные, без новой анимации; незавершённая прокрутка категории отменяется при смене страницы. Новых motion-токенов не добавлено.

## Поиск

Пользователь отдельно разрешил motion для всей поисковой механики 05.10.2026. Именованные presets: `searchHighlight`, `searchSurroundings`, `searchResultEnter`, `searchResultMove`. Фокус плавно выделяет поле и приглушает окружение до **20%**, как прямо указано пользователем (в прочитанном Figma 25%). Логотип и содержимое страницы остаются яркими. При blur окружение возвращается, запрос остаётся; Escape очищает поле и снимает фокус. Полоса sticky-категорий сохраняет непрозрачный фон, меняется opacity только её содержимого.

Новые результаты появляются одновременно с небольшим сдвигом, без каскадных задержек. Сохранившиеся товары имеют стабильные ключи и не начинают появление заново на каждую букву; Motion `layout="position"` плавно переставляет их, не масштабируя карточку. Удалённые совпадения убираются сразу: уходящих кликабельных копий нет. Ввод и покупка не ждут анимацию. Нулевая выдача использует те же карточки для восьми постоянных рекомендаций. При reduced motion opacity сразу 1, сдвиг 0 и layout-анимация отключена.

## Корзина

Статичная корзина от 05.10.2026 получает `dialogEnter`, `dialogExit`, `cartStateEnter`, `cartStateExit` на существующих длительностях и кривых. Первое открытие страницы не анимируется. Подтверждение сначала завершает выход диалога, затем меняет состояние; повторное нажатие не запускает второй сценарий. Диалог и его backdrop переходят за 240/110ms; native modal сохраняет блокировку фона до завершения выхода. Tab/Shift+Tab ограничены двумя кнопками, Escape/Cancel/фон отменяют, фокус после отмены возвращается к Clear cart. Empty state получает фокус заголовка.

`useReducedMotion` убирает смещение и длительность в диалоге/состояниях, CSS media query — hover и backdrop transition. При блокировке прокрутки сохраняется корневой scrollbar gutter; геометрия хедера не меняется. Cart в хедере сохраняет одновременно search opacity transition и собственный background hover. Статичные счётчики этапа 05.10 заменены интерактивными 06.10; анимация покупки каталога/PDP не затронута. Проверка: [cart-browser-audit.json](reference/cart-browser-audit.json). Системная reduced-motion настройка в браузере не эмулировалась.

Дополнение 06.10.2026: Amber Cart использует controlHover 150ms для фона/цвета, purchaseEnter 240ms для ширины и quantityChange 150ms для числа. Белый badge с чёрными цифрами растёт под несколько цифр; поиск сдвигается только при фактической смене ширины Cart, плавно. В строках суммы/числа и замена trash/minus — 150ms; удаление строки — 110ms opacity с inert, перестройка оставшихся — 240ms position. Клавиатурный фокус переходит к соседнему контролу; последняя строка передаёт его заголовку empty state. Прежний QuantityControl получил только значение 0 по умолчанию.

Промокод: debounce 400ms и mock validation 650ms — задержки обработки, не анимационные длительности. Loader использует исходный SVG 24px и цикл 700ms linear, только пока status=validating. Feedback — 150ms fade, изменение сумм — 150ms/4px; строка скидки плавно раскрывает высоту и отступ без отдельного скачка gap. CSS/React reduced motion отключают все новые переходы и вращение. Семь тестов test:cart проверяют модель/таймеры; девять test:motion по-прежнему проверяют scroll controllers. Браузерные сценарии: [cart-interactive-audit.json](reference/cart-interactive-audit.json).

Уточнение 06.10.2026: steps(8) у loader заменён на linear по обратной связи пользователя. Шаги 45° совпадали с симметрией восьмилучевой иконки, создавая видимость неподвижности. 24 браузерных замера подтвердили 19 различных промежуточных углов после правки; reduced-motion исключение сохранено. [Проверка](reference/cart-loader-counter-audit.json).

## Движение категорий

- Одновременно работает только одна анимация. Новый запрос останавливает предыдущую и начинает движение с текущей отображаемой позиции.
- Нативный `scrollLeft` сохраняет прокрутку и работу фокуса. Дробный остаток меньше пикселя выводится через `transform` внутренней полосы: короткая подсказка не прыгает между целыми пикселями.
- Округление вниз удерживает остаток неположительным и не расширяет правую границу прокрутки.
- Фейды вычисляются в том же кадре из фактической отображаемой позиции: `min(скрытая длина, 127px)`. Отдельного easing у них нет.
- Покадровое движение не вызывает React-render навигации. При наведениях сохраняются 12px, один отклик за посещение полосы и запрет на накопление сдвига.
- Клик закрепляет навигацию. Колесо/трекпад и начало touch-взаимодействия отменяют программное движение. Клавиатурный фокус отменяет старую анимацию перед раскрытием нового пункта, чтобы она не увела его за край.
- При размонтировании останавливается анимация и удаляется обработчик настройки reduced motion.

## Уменьшенное движение

`prefers-reduced-motion: reduce` отключает цветовые переходы и затухание навигации, обе прокрутки выполняет мгновенно. Для покупки, поиска и корзины [useReducedMotion](https://motion.dev/docs/react-use-reduced-motion) задаёт нулевую длительность и убирает сдвиги/масштаб/перестроение. Итоговые состояния сохраняются. При включении настройки в процессе прокрутки контроллер сразу заканчивает текущий маршрут.

## Дальнейшее применение

Checkout 8:18195 перенесён 06.10.2026. Переходы страниц остаются без entrance-эффекта. Неактивные бизнес-действия имеют aria-disabled и только hover/focus; ввод контактов read-only. Reduced motion отключает все новые CSS-переходы, общий AnimatedValue/PromoCodeField уже использует React-ветку. Проверка: `reference/checkout-browser-audit.json`; системное reduced motion в браузере не эмулировалось.

Новые состояния получают именованный preset в `tokens.js`. Для обычных действий использовать короткий отклик; длительные перемещения применять только при необходимости показать изменение положения. Возврат и прерывание проектируются вместе с появлением. Масштабирование самих карточек, bounce и бесконечные эффекты не применяются. Автоматическое появление используется в результатах поиска и смене состояния корзины; первоначальная загрузка обычного каталога остаётся без entrance-анимации.

Поисковая проверка: `reference/search-browser-audit.json`, экраны `search-focused.png`, `search-hover.png`, `search-results.png`, `search-empty.png`. В браузере зафиксированы промежуточные opacity и transform появления и затухания; это выборочные замеры, не полный покадровый performance-аудит. CSS/React-ветки reduced motion просмотрены, системная настройка в браузере не эмулировалась. Девять автоматических тестов по-прежнему проверяют контроллеры прокрутки, а не весь React-поиск.

Проверки: `npm run test:motion` (9 тестов), `npm run build` и сценарии из [design-qa.md](design-qa.md). Автоматические тесты запускают настоящий Motion с управляемыми кадрами и проверяют прерывание, передачу управления, отложенное завершение, границы, reduced motion и очистку. Последняя настройка hover/скролла — `reference/gentle-motion-audit.json`; полная проверка взаимодействий — `reference/lively-catalog-audit.json`; ранние этапы — `reference/motion-audit.json`. Это не замер производительности на всех устройствах. Системная reduced-motion настройка в браузере отдельно не эмулировалась.
