**Корзина подключена к общему состоянию каталога и PDP.** Cart становится Amber со счётчиком всех единиц и плавным hover. Поведение меню: наведение на пункт под фейдом даёт только **временный сдвиг 12px**. При уходе курсора с полосы позиция восстанавливается; переходы между пунктами под курсором не накапливают движение. Полноценная прокрутка остаётся по клику и смене активного раздела. Выбор правых категорий доводит полосу до реального конца: **Energizers с отступом 12px**, без пустого хвоста. Зазор до хедера обновлён до **20px** по D-25. [Короткий отклик при наведении](prototype/reference/menu-hover-hint.jpg).

Фейды теперь **динамические**: ширина равна скрытому за соответствующим краем участку, максимум 127px. При сдвиге на 12px новый фейд занимает только 12px и постепенно исчезает при возврате; первый активный пункт больше не накрывается сразу полной полосой затемнения. [Проверенный узкий фейд](prototype/reference/menu-dynamic-fade.jpg).

## Решения и основания

**D-37 — включение иллюстрации пустой корзины в deployment, 06.10.2026.** Пользователь сообщил о незагрузившейся 3D-картинке на опубликованном сайте. Исходный PNG 1 082 959 байт сохраняется без изменений; в `.vercelignore` добавлено явное исключение из запрета PNG, в source deployment он включён как binary/base64. `build:vercel` проверяет наличие обязательного UI-ресурса до восстановления каталога. Исправление заменяет ошибочное предположение D-36, что все растровые файлы корня assets устарели. При следующих публикациях включать этот файл и проверять пустую корзину отдельно.

**D-36 — публикация прототипа на Vercel, 06.10.2026.** Пользователь прямо запросил deployment под именем `prana-01`. Создан одноимённый проект в доступной команде MSGD; опубликован production deployment `dpl_3dugDydbgTYZkgbcsEoxRipvoJWo`, основной адрес https://prana-01.vercel.app. Корень приложения — `prototype/`, Vite, Node 24.x, установка `npm ci`, сборка `npm run build:vercel`, выход `dist/client`. `vercel.json` добавляет SPA fallback для прямых `/dish/:id`, `/cart`, `/checkout`, `/profile`. Большой снимок фото не передаётся в исходниках deployment: build восстанавливает 87 исходных versioned URL по `catalog-assets.json`, проверяя размер и SHA-256 каждого файла; браузер получает статичные файлы Vercel, live API каталога не добавлен. Изменение или исчезновение исходного изображения должно останавливать сборку. После повторного импорта каталога манифест нужно обновить из проверенного локального снимка. UI, бизнес-логика и Figma в этой итерации не менялись; Sites-конфигурация сохранена. Публикация ручная через подключённый Vercel, без Git auto-deploy и без автоматической синхронизации будущих изменений. Системные SF Pro не загружаются на хостинг; fallback на других устройствах остаётся ограничением. Разрешение на публикацию не приравнивается к новой визуальной приёмке или готовности реального магазина.

**D-35 — локальный профиль и календарь даты рождения, 06.10.2026.** Новый прямой запрос разрешает реализацию профиля, отложенную в D-34 и итерации крестика. Актуальный Figma `106:6035` прочитан перед переносом; макет не изменялся. Сетка 664 / 56 / 400px, Account y125, разделы и общий footer сохранены. Имя/телефон/email/DOB — образцы Figma. Сравнение черновика с сохранённым состоянием игнорирует крайние пробелы; возврат значений деактивирует Save. Локальное сохранение мгновенное, без имитации серверного запроса; Saved объявляется через status и сохраняет фокус кнопки. Данные и отдельная маркетинговая настройка сохраняются при внутренних переходах, сбрасываются после reload. Marketing переключает только демо-состояние, подписку не оформляет. React DayPicker 9.14.0 и Radix Popover 1.2.0 подключены отдельным ленивым модулем; месяц/год выбираются напрямую, даты хранятся локальным YYYY-MM-DD без UTC-сдвига, диапазон 1900–сегодня — UI-граница прототипа, не правило возраста. Календарь, hover, Saved и toggle используют общие 150/240/110ms и reduced motion. Заказы генерируются один раз на запуск из двух блюд и напитка каждый, с разными прошедшими датами и суммами в центах. Адреса, карты, баллы, expiry и logout остаются образцами; checkout-контакты не синхронизируются с профилем на этой стадии.

Дополнение к **D-31 от 06.10.2026**: по запросу пользователя стандартная очистка type=search заменена круглым SVG `142:14622` из актуального `129:10031` / поле `129:10048`. Оригинальный ассет сохранён без правки геометрии, 16px / inset 12px. Исходный #747474 осветляется CSS brightness(1 → 2) за общий controlHover 150ms; focus-visible повторяет hover, reduced motion отключает переход. Кнопка доступна только при непустом вводе, указатель/Enter очищают запрос и возвращают фокус в input. Focus scope охватывает input и крестик, поэтому Tab не восстанавливает окружающую навигацию раньше выхода из поиска; Escape сохраняет очистку и blur.

**D-34 — визуальный checkout с общим промокодом, 06.10.2026.** По запросу пользователя перенесён актуальный 8:18195, переход из корзины подключён; страница остаётся тупиковой. PromoCodeField и App-пromo переиспользованы без копирования контроллера. Состав и денежные суммы берутся из корзины. Имя/телефон/адрес/заметка read-only; доставка, switch, время, бонусы, карты и Place order — aria-disabled, только hover/focus. Alex, телефон/адрес, 476 points, June 7, *4344, повторные интервалы, Free и +$2 accrual — образцы Figma, не личные данные пользователя и не коммерческие правила; бонусы не меняют Total. Колонки 664 / 65 / 391px внутри 1120px, header/footer общие, отклики 150ms и reduced motion. Ограничение D-33 на переход checkout заменено; запрет реального заказа/оплаты сохраняется. На этапе D-34 профиль был отложен; впоследствии реализован по D-35. На момент D-34 публикация Vercel была впереди; выполнена позднее по D-36.

Дополнение к **D-33 от 06.10.2026**: пользователь положительно оценил работу корзины, но отметил визуально неподвижный loader и обновил Figma-счётчик. Badge теперь белый #FFF с чёрной цифрой #000; размер 16px и кнопка 107 × 36px сохраняются. Вращение loader — 700ms linear infinite во время проверки; steps(8) заменён, так как повороты по 45° совпадали с симметрией восьми лучей. Reduced motion по-прежнему отключает вращение.

**D-33 — общая корзина и локальная имитация промокода, 06.10.2026.** Прямой запрос пользователя заменяет независимые три позиции D-32. Единственный источник количеств — App; счётчик хедера показывает сумму единиц (как 6 для трёх строк по 2 в актуальном Figma). При 1 левая кнопка удаляет, при 2+ уменьшает. Суммы хранятся в центах, скидка 10% округляется до ближайшего цента на весь subtotal. Код `1111` задан пользователем; −10% взяты из предоставленного состояния Applied. Промокод необязательный, без Apply: 400ms debounce и 650ms имитации ответа, revision-защита от устаревших результатов, сброс при новом вводе/очистке корзины. Состояние сохраняется при внутренних переходах, но не после reload; постоянное хранение не добавлялось. Edit и реальные правила доставки остаются следующим этапом; переход checkout теперь реализован по D-34.

Историческое решение (статичные данные заменены D-33): **D-32 — статичная desktop-корзина.** По прямому запросу пользователя Cart открывает отдельную страницу с тремя товарами; очистка требует предупреждения, подтверждение показывает empty state, reload возвращает исходные позиции. Прочитаны текущие `74:5999`, `74:6015`, `80:5921`. Геометрия берётся из Figma, цвета — из нашей шкалы, старый хедер пустого состояния заменяется текущим общим 76px. Данные трёх блюд реальные, по две единицы каждого — демонстрационное наполнение. Состояние очистки отделено от количества каталога/PDP. Edit, плюс/минус, промокод и checkout пока отключены. Delivery Free — текст макета для статичной вёрстки, не утверждённое правило доставки. Amber 700 впервые назначен только статичному checkout через отдельную роль; остальные назначения не меняются.

## Как поддерживать документ и собирать отчёты

После каждой завершённой итерации обновляются дата, краткая сводка, текущее состояние и запись в журнале. Изменившиеся решения получают пояснение, что заменено и почему; история не переписывается так, будто прежних этапов не было. Новые проверки фиксируются с их реальными результатами. Непроверенное и согласование пользователя не выводятся из факта реализации.

Для **отчёта лиду** достаточно взять краткую сводку и записи за нужный период: результат, ценность для текущей задачи, ограничения, дальнейшие решения. Для **передачи разработке** — решения, таблицу поведения, карту реализации, проверки и незавершённый объём. Не включать в отчёт предположительные сроки, эффекты на метрики или согласования, которых не было.

Шаблон новой записи:

```markdown
### ДД.ММ.ГГГГ — название итерации

- Задача и основание:
- Результат и статус: макет / реализовано в прототипе / проверено / опубликовано.
- Изменившиеся решения:
- Что проверено и результат:
- Ограничения и открытые вопросы:
- Артефакты: макет, код, screenshot, QA или иной источник.
```
